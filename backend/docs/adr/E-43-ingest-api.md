# ADR-E43 — Telemetry Ingest API

**Status:** Accepted
**Date:** 2026-05-04
**Parent ADRs:** ADR-E41, ADR-E42

---

## 1. Decision

Implement three Next.js 15 Route Handlers — `POST /api/telemetry/batch`, `DELETE /api/telemetry/{deviceId}`, and `GET /api/health` — under `app/api/` (no `src/` prefix, matching the existing codebase layout). Shared infrastructure lives in `src/lib/` (`db.ts`, `auth.ts`, `logger.ts`) with the `@/` alias resolving to `./src/*` via `tsconfig.json`. The database singleton throws at import time when `DATABASE_URL` is absent. Authentication uses `crypto.timingSafeEqual` over SHA-256 digests of both keys to guarantee constant-time comparison regardless of input length. No SQL transaction wraps the ingest pipeline; the iOS retry contract makes this safe. Vitest module mocking uses `vi.mock('@/lib/db')` with the existing `@/` tsconfig path alias; `vitest.config.ts` must add `resolve.alias` for `@/` since it currently lacks it.

---

## 2. Context

**Binding constraints from ADR-E41:**
- Next.js 15 hybrid on Azure SWA Standard plan; `output: 'standalone'`. All files under `backend/`.
- Secrets (`DATABASE_URL`, `TELEMETRY_API_KEY`) in SWA Application Settings only; never logged.
- Node 20 runtime.
- `@neondatabase/serverless` is the sole database driver; no ORM.
- `tsconfig.json` defines `"paths": { "@/*": ["./src/*"] }`.

**Binding constraints from ADR-E42:**
- Exact column names on `devices` and `events` are a frozen contract; any deviation in E-43 SQL is a breaking change.
- `ON DELETE CASCADE` means a single `DELETE FROM devices WHERE device_id = $1` cascades all data — no application-level multi-DELETE.
- `parser_path` and `outcome` have no DB-level CHECK; Zod validation in E-43 is the sole gate.
- `last_upload_at` on `devices` is the column used for rate limiting.

**From E-43 spec:**
- Ingest endpoint gated solely by `X-Api-Key` header (not SWA role auth).
- Partial batch acceptance: 202 if at least one event is valid; invalid indices in `errors` array.
- No request body may ever appear in a log line.
- Per-device rate limit: one batch per 60 seconds.
- iOS retries entire batch on 5xx — event-insert/device-upsert eventual consistency is acceptable in v1.

## 3. Options Considered

### 3A. `DATABASE_URL` absence: throw at import vs. first call

**Throw at import time (chosen):** `neon(process.env.DATABASE_URL!)` at module evaluation. Missing env var throws synchronously before any route handler registers. Next.js build fails immediately; CI catches this in the `build` job, not during a live request. The spec T-4301 explicitly requires "confirm this fails CI clearly rather than at first request."

**Lazy initialization (rejected):** A missing `DATABASE_URL` surfaces only on the first request — a misconfigured deploy appears healthy to UptimeRobot and fails only on real ingest.

### 3B. Constant-time API key comparison

**SHA-256 digest + `timingSafeEqual` (chosen):**
```ts
import { createHash, timingSafeEqual } from 'crypto';
function safeEqual(a: string, b: string): boolean {
  const ha = createHash('sha256').update(a).digest();
  const hb = createHash('sha256').update(b).digest();
  return timingSafeEqual(ha, hb);
}
```
Both digests are always 32 bytes. Length differences in the inputs do not leak. This is the canonical Node.js pattern for variable-length secret comparison.

**Raw `timingSafeEqual` (rejected):** Requires equal-length buffers; naive padding leaks length information.

### 3C. File layout: `src/` vs root `app/`

No `src/` directory exists. The `tsconfig.json` alias `@/*` → `./src/*` was generated by `create-next-app --src-dir` but `app/` was placed at the repo root. The committed `app/api/health/route.ts` stub and ADR-E41's file plan both use the root `app/` for route handlers.

**Resolution (chosen):** `src/lib/` for shared code (matches the `@/` alias), root `app/api/` for route handlers (matches the committed stub). The Implementer creates `src/` if absent.

### 3D. Ingest pipeline transaction boundary

**No transaction in v1 (chosen per spec):** Rate-limit UPDATE → event INSERT → device UPSERT run as separate statements. If UPSERT fails after a successful INSERT, the iOS client retries on 5xx and the UPSERT completes on retry. Duplicate event rows are possible in extreme retry scenarios; accepted for v1.

**Wrapped in BEGIN/COMMIT (rejected):** Spec explicitly prohibits it; higher latency on Neon's HTTP-based serverless driver.

### 3E. Health endpoint: `Response.json` vs `NextResponse.json`

**`Response.json` (chosen for all new files):** Web Platform API, not Next.js-specific. The existing stub uses `NextResponse.json`; T-4304 replaces it with the standards-based form.

---

## 4. Rationale

Import-time throw on missing `DATABASE_URL` satisfies T-4301's CI-fail requirement with zero additional code. SHA-256 digest comparison eliminates the length-leak attack surface at negligible CPU cost vs. a network round-trip. The no-transaction decision follows the spec and is de-risked by the iOS retry contract. The split-root layout (`src/lib/` + root `app/api/`) is forced by the tsconfig alias and the committed stub — it is a well-known Next.js `--src-dir` scaffold variant.

---

## 5. Consequences

- All E-44 through E-46 Route Handlers must follow the same split-root convention.
- `@/lib/db` resolves to `src/lib/db.ts`; `src/` must exist before E-43 implementation begins.
- `vitest.config.ts` must add `resolve: { alias: { '@': path.resolve(__dirname, './src') } }` for `vi.mock('@/lib/db')` to work.
- Duplicate event rows are possible if iOS retries a partially successful batch; accepted for v1.
- Delete endpoint row counts may drift from the actual cascade result; accepted as a best-effort audit log.
- Rate-limit check adds two SQL round-trips for a brand-new device; T-4310 benchmark validates p99 < 1.5 s.

## 7. Public Interface Contract

### `GET /api/health`

```
Request:  GET /api/health  (no auth)
Response: 200  { "status": "ok", "timestamp": "<ISO 8601 UTC>" }
```
No database call. Response time < 100 ms warm.

### `POST /api/telemetry/batch`

```
Headers:  X-Api-Key: <key>
          Content-Type: application/json  (max 1 MB)

Body:
{
  "deviceId":     "<UUID v4>",
  "appVersion":   "<1–32 chars>",
  "modelVersion": "<1–64 chars>",
  "events": [                        // 1–100 items
    {
      "transcriptionAnonymised": "<1–2000 chars>",
      "intent":                  "<1–64 chars>",
      "slotsAnonymised":         { "<key>": <any> },
      "parserPath": "PersonalisationAlias" | "PersonalisationMemory" |
                    "FoundationModels" | "NLModel" | "KeywordRegex" | "Unknown",
      "outcome":    "confirmed" | "cancelled" | "timedOut" | "unknown",
      "locale":     "<ll-CC>",
      "timestamp":  "<ISO 8601 with offset>",
      "flags":      ("likelyMisparse" | "recoverableUnknown" | "broadcast")[]
    }
  ]
}

Responses:
  202  { "accepted": <int>, "rejected": <int>, "errors": [{ "index": <int>, "reason": "<str>" }] }
  400  { "error": "Invalid request body", "detail": "<reason>" }
  401  { "error": "Invalid API key" }
  413  { "error": "Batch too large" }
  429  Retry-After: 60  { "error": "Rate limit exceeded", "retryAfterSeconds": 60 }
  500  { "error": "Server error" }
  503  { "error": "Database unavailable" }
```

Field mapping to `events` table columns:
- `deviceId` → `device_id`
- `events[i].timestamp` → `client_timestamp`
- `events[i].transcriptionAnonymised` → `transcription_anonymised`
- `events[i].slotsAnonymised` → `slots_anonymised` (JSONB)
- `events[i].flags` → `flags` (TEXT[])
- `appVersion`, `modelVersion` denormalised onto every event row
- `locale` from `events[0].locale` for device UPSERT

### `DELETE /api/telemetry/{deviceId}`

```
Headers:  X-Api-Key: <key>

Responses:
  200  { "deleted": { "devices": <int>, "events": <int>, "labels": <int> } }
  400  { "error": "Invalid deviceId" }
  401  { "error": "Invalid API key" }
  500  { "error": "Server error" }
```
Idempotent — non-existent device returns 200 with all counts 0.

## 8. Conflicts Flagged

**C-1 (resolved in this ADR):** Spec references `src/app/api/...` and `src/lib/...`, but `app/` is at the repo root (no `src/`). Resolution: `src/lib/` for shared code, root `app/api/` for route handlers. Implementer must `mkdir src/lib` as the first step.

**C-2 (non-blocking):** T-4311 describes both a single multi-subquery SELECT and a RETURNING clause on the DELETE in different readings. This ADR adopts: two-statement approach — SELECT counts first, then DELETE. Minor count drift is explicitly accepted.

**C-3 (non-blocking — implementer action required):** `vitest.config.ts` currently has no `resolve.alias` for `@/`. Without it, `vi.mock('@/lib/db')` fails to resolve. The Implementer must add the alias before writing unit tests.

**C-4 (non-blocking):** Wrong API key → 401 + WARN log. Missing `X-Api-Key` header → 401 + no log. Both return identical `{ "error": "Invalid API key" }` bodies. Implementer must not distinguish in the response.

**C-5 (non-blocking):** Two simultaneous first-batch requests from the same device both pass the rate-limit check and both insert events. The device UPSERT uses `ON CONFLICT DO UPDATE` — no duplicate key error. Accepted per iOS upload schedule.
